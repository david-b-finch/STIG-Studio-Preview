Try these workflows

  1. Open 01. Try status hotkeys, Next Not Reviewed, filters, Findings/Comments, saving and reopening.
  2. Compare 01 with 02: three changed rules. Import Assessment proposes changes to those same three rules before adjusting import options.
  3. Compare Apache 06 with 09: four changed rules across Site and Server. Other rules match.
  4. RHEL 04 includes one intentionally Open rule with no Finding Details, for the assessment-gap filter.
  5. Files 03, 05 and 07 contain only Not Reviewed rules with blank assessment text. File 10 is the compact Firefox update: 9 unchanged, 2 changed, 1 removed rule.
  6. Combine 04 and 06 to produce three STIGs for the same fictional web host; 08 is the prebuilt 34-rule result. Adding 09 exercises rule conflicts. Check filesystem modification times after downloads/extraction.

Additional Viewer fixture

Viewer 3 multi-checklist CKLB: 15 STIG entries and 164 demo rule records, with blank/default asset data. Its STIG/rule fields match the generated demos. It contains repeated families and releases; use it for open/save fidelity, and use numbered pairs for ordinary comparisons. It is separate from the ten-file ZIP.

Reference identities, titles, instructions, versions/releases and nested groups are preserved. Full raw source XML was omitted to keep the samples small. The manifest records fixture creation hashes; the latest application snapshot hash is listed in the preview README. Full Viewer GUI interoperability is not certified.
