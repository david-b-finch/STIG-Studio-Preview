STIG Studio v0.7.7

Experimental preview · Snapshot build · Not a validated release

An offline-first, browser-based tool for viewing and editing STIG checklists, comparing assessments, and combining asset checklists. This public preview is for usability feedback and controlled testing.

EXPERIMENTAL — DO NOT USE FOR OPERATIONAL ASSESSMENTS

This build has known or suspected data-integrity risks affecting conversion, comparison, and combined exports. It has not passed a full regression or interoperability test suite. Do not rely on the exported results for authorization, compliance, or production reporting.

Use synthetic or fully sanitized test files only. Do not load classified, controlled, sensitive, or actual system assessment data into this public test deployment.

What to try

  • Compare v0.7.7 with v0.7.6 using the Open or Download buttons above.
  • Try the demo comparisons, multi-STIG Apache checklists, and original reference downloads above.
  • Open STIG Library, add the reference ZIP/XML, export a library file, reopen it, and create an unreviewed checklist.
  • Edit synthetic working data, check Autosave, reload, and try recovery. Clear All Browser Recovery removes recovery copies and pauses autosave while keeping open work.
  • Try stacked Finding Details/Comments, Tabs/Sections, and rule status hotkeys 1/N, 2/O, 3/X, and 4/R.
  • For a minimal one-rule example, use Import STIG Reference Archives with the synthetic reference ZIP or XML, then save the new assessment.
  • Change a test rule's status, comments, or finding details.
  • Try Next Not Reviewed and Import Assessment with the comparison reference fixture.
  • Select rules and try Bulk Edit, Undo Bulk Edit, and Selection help.
  • In comparison, use Bulk Edit to copy Reference Comments or Finding Details into blank working fields. Current statuses stay unchanged unless explicitly edited; preview, cancel and undo the copy.
  • Open Advanced Filters directly above the rule list, including when Quick Filters is collapsed.
  • Use Export / More for CSV and printable HTML reports; verify filtered and selected scopes.
  • Save the file and verify the exported data independently.
  • Test comparisons, advanced filters, and asset combining.
  • Test in Firefox and Chromium-based browsers.

Give useful feedback

  • Specify browser and version.
  • Describe the exact steps needed to reproduce the problem.
  • Explain expected behavior versus actual behavior.
  • Attach only synthetic or sanitized sample data.
  • Indicate whether saved files re-open successfully.

Feedback is collected through public GitHub Issues; do not post sensitive data.

Privacy and local processing

Source inspection indicates that checklist parsing and export occur in your browser without an application server or intentional checklist uploads. This is not an independent security audit.

GitHub may process ordinary site-visitor information. Files you save are downloaded through your browser. In v0.7.7, working assessments autosave to this browser for recovery when storage is available; use Autosave → Clear All Browser Recovery to remove those copies. Library changes need an explicit Export Library. Browser recovery does not replace file backups.
